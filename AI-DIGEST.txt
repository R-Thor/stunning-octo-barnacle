AD-DIGEST — Studio Architecture
Version: 1.0.0
Codename: studio-architecture

This digest defines the rules, structure, and deterministic access model for the Studio Architecture project. It ensures that AI systems and human contributors interact with the repository consistently, safely, and without ambiguity.

-------------------------------------------------------------------------------
SECTION 0 — CONTRACT RULES
-------------------------------------------------------------------------------

0.1 Deterministic Access
- The AI must never guess file paths.
- Only files listed in file.index may be referenced.
- If a file is not in file.index, it does not exist.

0.2 Version Awareness
- All file URLs require an explicit {{GIT-REF}}.
- The digest URL provided by the user implicitly supplies {{GIT-REF}}.
- The AI must not assume a default branch or commit.

0.3 File Index Authority
- file.index is the authoritative list of all files in the repository.
- It is maintained manually by the project owner at this stage.
- The AI must treat file.index as the single source of truth.

0.4 No Assumptions
- The AI must not infer folder structure, file purpose, or relationships beyond what is defined in this digest.
- The AI must not invent files, directories, or architecture.

-------------------------------------------------------------------------------

-------------------------------------------------------------------------------

2.1 Root (/)

2.3 .github/workflows/
Contains GitHub Actions workflows (if present).
These workflows may automate tasks such as validation, linting, or deployment.

2.4 src/ (if present)
Contains source code for the Studio Architecture system.
Subfolders define modules, components, or services.

2.5 docs/
Contains human-readable documentation, design notes, and architectural references.

SECTION 3 — ARCHITECTURE SUMMARY
-------------------------------------------------------------------------------

The Studio Architecture project defines a deterministic, modular, and AI-friendly environment for building reproducible development studios. Its goals include:

- Zero host pollution
- Deterministic environment setup
- Modular tooling
- Clear separation of concerns
- AI-navigable repository structure
- Future-proof documentation

The architecture is built around three pillars:

3.1 Deterministic Structure
The repository must remain predictable, explicit, and free of ambiguity.

3.2 Documentation Contracts
This digest defines how AI systems interact with the repo.
It prevents hallucination and ensures safe, consistent reasoning.

3.3 Modular Tooling
Scripts, configs, and modules must be isolated and composable.

-------------------------------------------------------------------------------
SECTION 4 — ASSISTANT BEHAVIOR
-------------------------------------------------------------------------------

4.1 File Access
- Always load file.index first.
- Never reference files not listed in file.index.

4.2 Updates and Modifications
- The AI may propose improvements or documentation updates.
- The AI must not modify automation scripts unless explicitly instructed.
- The AI must preserve determinism in all outputs.

4.3 Reasoning Boundaries
- The AI must base reasoning on the repo’s actual structure.
- The AI must not hallucinate architecture or undocumented relationships.

4.4 Digest Integrity
- This digest is the authoritative contract.
- If inconsistencies are detected, the AI must notify the user.
